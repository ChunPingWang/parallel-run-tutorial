# ADR-001：流量取得方式 —— 錄製重放 vs 即時鏡像

- **狀態**：已接受
- **日期**：2026-07-25
- **決策者**：應用架構 / 平台維運 / 資安

## 背景

需以生產真實流量驗證新舊應用等價性。可選路徑分兩類：
1. **即時鏡像**（Nginx `mirror`、Envoy `request_mirror_policies`、APISIX/Kong `proxy-mirror`、Diffy）
2. **錄製後離線重放**（GoReplay）

本案舊應用在 VM、新應用在容器，且**無 Service Mesh**，正線為銀行核心交易路徑。

## 決策

**功能比對與性能驗證皆以 GoReplay 錄製重放為主方案；即時鏡像列為備案，僅在「必須即時發現差異」為硬需求時採用。**

## 理由

| 面向 | 錄製重放 | 即時鏡像 |
|---|---|---|
| 正線改動 | **零**（agent 監聽網卡） | 需在流量路徑插入閘道 |
| 新增故障點 | 無 | 有（閘道本身） |
| 倍率放大 | **支援**（`\|500%`） | 不支援 |
| 背壓控制 | 有 | 無 |
| 回應比對 | 錄製檔內含新舊回應，離線 diff | 回應直接丟棄，需另建管線 |
| 樣本可重複使用 | **可**，同一份檔重跑多次 | 不可 |
| 即時性 | 分鐘～小時級延遲 | 秒級 |

決定性因素是**正線零改動**與**倍率放大**。性能驗證尤其只能走錄製重放：mirror 無法產生超過 1x 的負載，也沒有背壓控制，不適合容量驗證。

## 後果

**正面**
- 正線風險最低，回退僅需停止 agent
- 同一份錄製檔可反覆用於迴歸，新版本修正後直接重跑
- 離線比對不受時間壓力，可做深度分析

**負面**
- 無法即時發現差異，缺陷回饋週期較長
- 錄製檔含生產資料，衍生個資與保留政策成本（見 ADR-007）
- agent 佔用正線 VM CPU，需事前實測（檢核表 T-11）
- 時序相依的流程（如同一 session 連續操作）重放時可能失序

## 替代方案

| 方案 | 未採用原因 |
|---|---|
| Nginx `mirror` | 主連線在子請求結束前不釋放，新系統變慢會拖累正線；無法放大倍率 |
| Envoy mirror | 真非同步、可熱調比例，但仍需插入閘道，且回應丟棄 |
| Istio | 本案無 Service Mesh，為 PoC 導入 mesh 成本過高 |
| Diffy | 噪音消除設計優秀，但仍屬即時鏡像，且需額外維運一套服務 |

## 備註

Diffy 的「先建立噪音基線再比對」思路本案完整沿用，僅實作方式改為自建（見 ADR-004）。
